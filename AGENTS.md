# Working on Falkenwarte

This repository is the reviewed, reusable source for a **personal Pi installation**, not a template to copy wholesale into every project. Pi and Node.js 22+ are prerequisites. The checkout path varies by machine; never hardcode this user's home directory, provider credentials, GitHub owner or project number into tracked configuration. Falkenwarte is the approved profile name. Each adopting project owns its own `.falkenwarte/knowledge/`; it does not replace Pi's trusted `.pi/` settings.

## Ownership and verification

- `config/` declares managed Pi preferences, local/remote packages, personality sources and safe MCP entries. `scripts/portable-pi.mjs` applies them without overwriting unmanaged state. Read [`docs/portable-profile.md`](docs/portable-profile.md) before changing ownership or capture behavior.
- `extensions/pi-personalities/` owns role selection and its Pi smoke tests; `personalities/` owns the actual prompts. `extensions/pi-subscription-status/` owns optional provider quota display; `extensions/pi-factory-flow/` owns the manual Pi task-flow view; `themes/pi-atlavium/` owns theme tests and previews; `skills/pi-portable-skills/` owns reviewed skills and the locked browser CLI. Keep packages independent and update package manifests and tests together.
- Run `node --test tests/portable-pi.test.mjs`, `npm --prefix extensions/pi-personalities test`, `npm --prefix extensions/pi-personalities run smoke`, `npm --prefix extensions/pi-subscription-status test`, `npm --prefix extensions/pi-subscription-status run smoke`, `npm --prefix extensions/pi-factory-flow test`, `npm --prefix extensions/pi-factory-flow run smoke`, `npm --prefix themes/pi-atlavium test`, `npm --prefix skills/pi-portable-skills test`, and `node --test tests/falkenwarte-project.test.mjs` for affected changes. Run `node scripts/portable-pi.mjs plan` before `update`; do not run `update --force` over a conflict without explicit review. `capture --dry-run` is read-only, but a real capture requires inspecting every changed value before committing.
- Credentials, sessions, browser state, generated machine paths and other people's packages stay outside Git. Inspect `git diff --cached --check` and staged paths before each Conventional Commit (`feat(scope):`, `fix(scope):`, `docs(scope):`, `test(scope):`, `chore(scope):`). Do not commit automatically after a failed test.

## Decisions and delegated work

Use [`docs/adr-workflow.md`](docs/adr-workflow.md) when a change commits the profile or a target project to a consequential technical or domain choice. The reusable `adr-decision` skill contains a template; this repository stores its records in [`.falkenwarte/knowledge/decisions/`](.falkenwarte/knowledge/decisions/README.md) and evidence-backed domain stories/models in [`.falkenwarte/knowledge/domain/`](.falkenwarte/knowledge/domain/README.md). A separate project's records belong to *that project*; respect its existing archive, or use `node scripts/falkenwarte-project.mjs init /path/to/project` after adoption. Waldemar coordinates, Albert tests domain language where useful, Brunhilde challenges architecture, and the user approves consequential decisions. Avoid ceremonial delegation and keep each child read-only unless its task explicitly grants an isolated write boundary; Waldemar owns integration and final tests.

For project work, read that project's `AGENTS.md` before acting. The factory works only in the checkout the operator supplies; never create, delete, switch, merge, or backmerge its worktrees. Do not run concurrent writers in the same checkout. Pi natively uses `.pi/` for trusted project settings. `.falkenwarte/` is Git-reviewed Markdown knowledge, not an extension loader or a replacement for project trust. Do not copy this profile's project-specific records into another repository. GitHub Issues and Projects are optional external work tracking, not the decision archive: consult `github-issues-projects`, confirm the actual target repository, and obtain authorization before remote mutations. No GitHub authentication details belong here.

## Seeing the work

Use pi-subagents' FleetView or `/subagents-fleet` for live child activity, and the decision's compact Mermaid diagram for durable architecture when it adds clarity. The existing Powerline footer remains one line. Use `/factory start <task or GitHub Issue URL>` in the operator-provided checkout. Automatic launch is optional and **disabled for this repository** until effective worker tool permissions are constrained; see [`extensions/pi-factory-flow/README.md`](extensions/pi-factory-flow/README.md) for review and explicit publication gates. [`docs/future-directions.md`](docs/future-directions.md) separates this from unimplemented GitHub and PR automation. The footer may show a live OpenAI Codex weekly quota only when that provider exposes a valid seven-day window; never infer it from session tokens.
