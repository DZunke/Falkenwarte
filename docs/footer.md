# Footer layout

The third-party [pi-footer extension](https://github.com/wobondar/pi-footer) renders this setup's status line. Its `powerline` preset is the starting point, not a theme managed by Pi itself. We keep the resulting JSON under [`extensions/pi-footer/config.json`](../extensions/pi-footer/config.json) and apply it to the extension's default `extensions/pi-footer.json` location in Pi's agent directory.

The single line retains the powerline preset's model/provider, Git branch, token count, context bar, output speed and time segments. Filled powerline blocks and spaced hard separators matter here: bare separator glyphs were hard to read. The blocks now use a warm Atlavium-inspired palette—dark brass anchors around parchment, muted gold and a restrained sage segment—instead of the previous red-heavy dark colors. Every block's fixed ink/cream text has at least 4.5:1 contrast against its ANSI 256 background. Some icons and separators expect a Nerd Font-compatible terminal font. Upstream `pi-footer` supports Pi theme colors for **foregrounds**, not backgrounds; these backgrounds are fixed ANSI colors chosen to work alongside both Atlavium variants, rather than changing automatically with the theme.

The active personality is a compact badge aligned to the **right of the same line**. [`extensions/pi-personalities/index.ts`](../extensions/pi-personalities/index.ts) publishes a human-readable name such as `Waldemar` under the `pi-personalities` status key. The `external-status` widget reads that key, adds an icon, and hides when no personality is active. `pi-footer` would otherwise append the same status as a second line, so `extensionStatusRow.hiddenKeys` suppresses that duplicate without hiding the inline badge. The right-aligned badge repeats the dark-brass/cream treatment of the model block. Other extensions publishing new status keys can still create a separate status row; hide those keys in `/footer` if you want to retain one line.

To change the layout, open `/footer` in Pi, save your edits there, then run `node scripts/portable-pi.mjs capture --dry-run` and `capture`. Review `git diff -- extensions/pi-footer/config.json` before committing. The footer config contains stable widget IDs so unrelated settings changes do not regenerate it. `capture` requires the powerline preset, one line, the inline personality widget and suppression of its duplicate status row; if you intend to change that policy, review the repository configuration explicitly first.

The package is pinned in [`config/packages.json`](../config/packages.json), currently to commit `e339196b1ee0285b5dc9508a6e4d61aff5dc4fb2`. Check upstream changes before moving that pin. The plugin's own configuration UI and JSON schema are upstream responsibilities; this checkout only owns the chosen layout and the personality integration. Review [profile ownership](portable-profile.md) for its destination and [updates](updates-and-capture.md) for the pin-change workflow.
