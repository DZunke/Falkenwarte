# ADR-0012: GitHub-Lieferkette und dokumentierte Entwicklung

**Status:** accepted für Konzeptfassung 2.0; Umsetzung und Abnahme offen.  
**Datum:** 19. November 2026.

## Kontext

Falkenwarte selbst wird auf GitHub entwickelt. QA, Versionierung und nachhaltige Fachbeschreibung sollen von Beginn an reproduzierbar sein.

## Entscheidung

Conventional-Commit-PR-Titel und Squash-Merge speisen Release Please. PRs durchlaufen statische QA, Build und E2E. Ein eng berechtigter GitHub-App-Token im vertrauenswürdigen Releasejob ermöglicht reguläre Release-PR-QA. Ein veröffentlichtes Image gehört exakt zum geprüften unveränderlichen Release-Commit.

## Konsequenzen

Die laufende private App erhält keine GitHub-Rechte. Dokumentation wird gemeinsam mit Fachregeln und Verträgen gepflegt und statisch unter /docs bereitgestellt. Release Please veröffentlicht nicht automatisch auf dem privaten Host. Token-Auslöseregeln werden nach aktuellem GitHub-Vertrag dokumentiert.

## Betrachtete Alternativen

Ein manuell gepflegtes Changelog und ungebundene latest-Images erschweren Nachvollziehbarkeit. Ein separates ungepflegtes Wiki würde die Verbindung zu Fachänderungen verlieren. Releasejobs aus untrusted PR-Code dürfen keine App-Secrets erhalten.
