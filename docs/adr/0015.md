# ADR-0015 · QA für den Release-Pull-Request

**Status:** accepted

**Datum:** 19. November 2026

## Entscheidung

Release Please erstellt den Versions-PR mit dem GitHub-Token des Releasejobs. Der Job liest Branch und Commit dieses PR über die GitHub-API und startet den QA-Workflow per `workflow_dispatch`. Die Titelprüfung vergleicht den ausgecheckten Commit mit dem erwarteten SHA. Ein neuer Commit benötigt einen neuen Prüflauf.

## Begründung

Von GitHub Actions erzeugte Ereignisse lösen mit dem Standardtoken nur bestimmte Folgeworkflows aus. Der explizite Start bietet dem Versions-PR denselben erforderlichen Gesamtcheck wie einem gewöhnlichen PR und benötigt kein zusätzliches persönliches Token.

## Auslieferung und Abnahme

Nach dem Merge prüft der QA-Workflow den Commit auf `main`. Der Veröffentlichungsjob lädt das Linux-Image aus genau diesem erfolgreichen Lauf, prüft Image-ID, Revision und Tag und überträgt es an GHCR. Das Release enthält das zugehörige Digestmanifest.
