# ADR-0002: DBAL, SQLite und atomare History

**Status:** accepted für Konzeptfassung 2.0; Umsetzung und Abnahme offen.  
**Datum:** 19. November 2026.

## Kontext

Domainobjekte sollen unabhängig von ORM-Lebenszyklen bleiben. Ein einzelner Produktionscontainer benötigt einen lokalen persistenten Speicher. Fachänderungen und Verlauf dürfen nach Fehlern nicht auseinanderlaufen.

## Entscheidung

Doctrine DBAL und explizite Migrationen verwenden SQLite auf lokalem Volume. Zustand, Objektversion, redigierte Revision, Domain Events, Outbox und lokaler Actionabschluss werden in einer kurzen eigenen DBAL-Transaktion geschrieben. Doctrine ORM und orm-pack sind ausgeschlossen.

## Konsequenzen

Repositories rekonstruieren Aggregate explizit. Nebenläufige Writer werden begrenzt; WIP-/Abhängigkeitsregeln verwenden Scope-Sperren beziehungsweise atomare Reservierungen. HTTP findet außerhalb der Fachtransaktion statt. Ein Wechsel zu einem anderen SQL-System benötigt eine eigene Entscheidung.

## Betrachtete Alternativen

Vollständiges Event Sourcing ist für den Umfang nicht nötig. Eine ORM-abhängige Messenger-Transaktionsmiddleware ist keine DBAL-only-Lösung. Reine Snapshots ohne Ereignisse würden zuverlässige Folgearbeit erschweren.
