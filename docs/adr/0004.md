# ADR-0004: T3 führt aus; Falkenwarte referenziert Ziele

**Status:** accepted für Konzeptfassung 2.0; Umsetzungs- und Abnahmenachweis siehe [Traceability](../TRACEABILITY.md).

**Datum:** 19. November 2026.

## Kontext

Provider, Modelle und Arbeitsbereiche existieren bereits in T3. Falkenwarte soll deren Aufgaben koordinieren, ohne eine zweite Provider- oder Codeplattform aufzubauen.

## Entscheidung

Rollen referenzieren den T3-Projektstandard oder einen vorhandenen T3-Referenzthread. Der Adapter löst die tatsächlich benötigten nativen Einstellungen in T3 auf. Falkenwarte besitzt keine Modellzuordnungs-, Home-, Repository- oder Worktreeverwaltung. Native Pi-Unterstützung wird ohne Nachweis nicht vorausgesetzt.

## Konsequenzen

Die gesendete Startpayload wird eingefroren. Ein Referenzthread liefert aufgelöste Routingwerte. Ohne modelSelection bestimmt T3 seinen Projektstandard erst bei erster Annahme; ein Replay dieses angenommenen Starts erhält die dann gespeicherte Zuordnung. Fehlende oder unlesbare Ziele blockieren erklärbar. Standardmäßig ist ein aktiver Run pro T3-Projektbindung erlaubt. Ein separat laufender Pi-Agent kann Falkenwartes MCP verwenden; das macht ihn nicht automatisch zu einem T3-Ausführungsprovider.

## Betrachtete Alternativen

Direktes codex exec im Appcontainer würde eine zusätzliche Laufzeit und Zugangskonfiguration schaffen. Ein T3-Fork ist für den nachgewiesenen MCP-Umfang nicht erforderlich; eine künftig fehlende Fähigkeit würde separat bewertet.
