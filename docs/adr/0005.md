# ADR-0005: Dauerhafte Runs und Abgleich externer Zustände

**Status:** accepted.

**Datum:** 19. November 2026.

## Kontext

Ein T3-Lauf überdauert einen HTTP-Aufruf. Eine verlorene Startantwort, ein früher Agentbericht oder ein Netzwerkfehler darf nicht ohne Prüfung als erfolgreicher Abschluss gelten.

## Entscheidung

Falkenwarte speichert Run und Startidentität lokal, bevor ein dauerhafter `run.dispatch`-Auftrag den T3-Start ausführt. Spätere Hintergrundaufträge beobachten oder gleichen den externen Zustand ab. Agentberichte werden anhand ihrer Run-, Versuchs- und Revisionsreferenzen zugeordnet.

## Konsequenzen

Eine angenommene Action und ein erfolgreicher Run sind unterschiedliche Zustände. Der `runs_abandon`-Command aktualisiert nur den lokalen Run-Datensatz. Er sendet keinen T3-Abbruch und setzt keinen T3-Abschlussstatus.

Run-Completion für eine Workflowphase und Task-Completion für die ganze Aufgabe verwenden getrennte Regeln. Ein Netzwerkretry erhöht nicht automatisch die fachliche Reparaturrunde. Der Consumer dedupliziert lokale Aufträge über `inbox`. Externe Wirkung hängt vom jeweiligen Providervertrag ab.

## Betrachtete Alternativen

Nur auf Agentcallbacks zu warten ließe verlorene Meldungen ungeklärt. Ein dauerhaft blockierender Worker würde einen Ausführungsprozess belegen, ohne die Unsicherheit des externen Zustands zu beseitigen.
