# Falkenwarte: next visualization choices

The user chose **Falkenwarte** for the portable Pi profile, with Falkensee retained as Waldemar's house and roleplay background. [ADR 0002](../.falkenwarte/knowledge/decisions/0002-project-owned-knowledge.md) records its Git-reviewed project knowledge directory. A small [Pi task-flow prototype](../extensions/pi-factory-flow/README.md) is now installed locally; the full GitHub/PR pipeline described below remains a proposal. `.falkenwarte/` is not an executable loader. Check naming availability and rights before publishing a public package.

## Better views without a second source of truth

1. **Now — live work:** use pi-subagents' existing FleetView, compact phase labels, `/subagents-fleet` inspector and `/subagent-cost`. This already shows which specialist runs, its status, recent output and cost. Avoid another persistent footer row: [`extensions/pi-footer/config.json`](../extensions/pi-footer/config.json) intentionally has one readable Powerline line.
2. **Now — durable reasoning:** put a small Mermaid context map or state transition in a project ADR when it helps explain an alternative. Pi 1.5.2 supports Markdown Mermaid rendering through `markdown.mermaid`; a plain Markdown diagram stays reviewable on GitHub and is useful without a running dashboard.
3. **Now — manual task flow in Pi:** `/factory start <task or Issue URL>` shows a compact widget and `/factory` opens a Pi screen; Waldemar can add self-reported milestone summaries with `factory_progress`, and observed child receipts appear as *unlinked session activity* until explicitly bound to the task. The [full proposed flow](factory-flow.md) extends this to read-only GitHub intake, live background agents, review gates and authorized PRs with real evidence. [Phase labels](factory-github.md) remain a proposal for a selected repository; the extension does not mutate GitHub.

The [Agentheim repository](https://github.com/heimeshoff/Agentheim) illustrates a richer model: its `.agentheim/` separates `knowledge/` from `board/`, with a read-only dashboard projecting those files. That boundary is useful inspiration, but its Claude Code plugin, full task lifecycle and bridge stack should not be copied into this Pi profile. Pi already recognizes **trusted** project `.pi/` settings and `AGENTS.md`; `.falkenwarte/knowledge/` now holds reviewed Markdown, but Pi does not load it automatically; any future executable integration needs a separate design and trust review. Compare existing Pi and pi-subagents surfaces first, then approve a design on an actual project need via [`docs/adr-workflow.md`](adr-workflow.md).

Sources: [Agentheim README](https://github.com/heimeshoff/Agentheim#readme), [GitHub CLI Projects manual](https://cli.github.com/manual/gh_project), and [`pi-subagents` observability guidance](https://github.com/nicobailon/pi-subagents/blob/main/docs/observability.md). The last link describes upstream behavior; verify it against the pinned version before changing integration. Pi is the approved first surface. Validate the prototype with an actual assignment before adding automatic GitHub writes, an event log, or a browser view.
