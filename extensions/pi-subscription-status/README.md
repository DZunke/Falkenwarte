# pi-subscription-status

This local Pi extension adds an optional `falkenwarte-usage` status to the existing single-line `pi-footer` model block. It never replaces Pi's footer. On an interactive session using the native `openai-codex` OAuth provider, it makes a read-only request to `https://chatgpt.com/backend-api/wham/usage` with credentials resolved by Pi, selects only a valid seven-day quota window, and displays `W 98%` for 98% weekly capacity remaining. The footer hides the segment for other providers, missing credentials, an expired or malformed window, errors, and offline startup. `/falkenwarte-usage` requests a fresh check and shows used/remaining percentages and reset time.

The endpoint is provider-specific and undocumented; it may disappear or change. Requests refuse redirects, time out after seven seconds, and poll every five minutes while interactive (model changes and explicit checks can trigger earlier requests). The token, account ID and provider response are held only in memory during a request, never persisted or printed. Pi's own authentication may refresh the credential as part of its normal auth path. No number is inferred from local session tokens or a separate Codex CLI login. The user can omit this local package from a machine's Pi configuration if the extra request is unwanted.

Run `npm test` for parser and malformed-response cases and `npm run smoke` for offline Pi extension discovery. These tests do **not** probe a private account. The portable setup's `update` command runs both and verifies `/falkenwarte-usage` loads; see [`docs/footer.md`](../../docs/footer.md) for placement and the privacy boundary.
