# Domain evidence for this project

Domain notes here describe **the portable Falkenwarte profile**, not the business rules of a project it later visits. Albert investigates unclear language with the relevant expert; Waldemar maintains the reviewed record. Use the portable `ddd-domain-discovery`, `ddd-strategic-modeling` and `domain-story-mapping` skills as methods, not as facts.

- [`stories/`](stories/README.md) — one concrete scenario per note: actors, events, exceptions, sources and the next question.
- [`models/`](models/README.md) — a scoped glossary, model and only evidence-backed boundaries and invariants.

Begin with the smallest scenario or decision the assignment requires. Mark a domain model `Draft` while a rule lacks expert confirmation. Context maps are optional; do not invent bounded contexts from folders, deployables or database tables. If the target repository already has domain documentation, link and extend it instead of creating a competing `.falkenwarte` archive without approval.
