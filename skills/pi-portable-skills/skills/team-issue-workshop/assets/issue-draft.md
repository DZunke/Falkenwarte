# Issue draft checklist

Use only sections supported by the conversation. Remove placeholders before showing the user the final body.

## Outcome

Who benefits, and what should be different when this is done?

## Context

What happens today? Link observed behavior, related Issues or accepted project decisions when known. Separate evidence from assumptions.

## Acceptance examples

- Given [realistic starting situation], when [relevant action], then [observable result].
- Include a failure or recovery example when it matters.

## Scope and non-goals

Name the smallest useful increment and what this Issue does not decide or implement.

## Risks and open questions

Record unresolved specialist findings and decisions the implementer must obtain; do not silently choose an architecture.
